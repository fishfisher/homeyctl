# homeyctl audit and AI builder upgrade

Date: 2026-09-22. Scope: CLI commands, HTTP/config/authentication paths, flow and
variable safety, embedded agent skill, dependencies, tests, CI, and release setup.
This is a code and compatibility audit, not a certification that every installed
Homey app or physical automation behaves correctly.

## Delivered changes

| Area | Finding | Result |
| --- | --- | --- |
| Flow updates | Backups were optional; partial ordinary-flow updates failed validation; incomplete advanced cards could destroy fields | Mandatory full-document backups, local merge, complete-result validation, read-back verification, dry-run |
| New AI flows | No enforced review folder or disabled mode | `flows create --ai` forces disabled and the root AI Flows folder |
| Graph validation | No comprehensive canvas/reference checks | Eight card types, coordinates, ports, edges, ALL inputs, reachability warnings, offline and online validation |
| Recovery | No deliberate whole-graph restoration option | `--replace-cards`, local null-card deletion convention, full resulting API payload, backup-before-restore |
| Name resolution | Duplicate names could select an arbitrary flow/device/variable | Ambiguous names rejected; exact IDs preferred |
| Logic values | Invalid booleans silently became false; number parsing accepted prefixes | Strict boolean and finite-number parsing; collision checks |
| Large variable batches | No reviewed manifest or partial-failure record | Plan/apply, reuse without resets, count/hash confirmation for 10+, namespace for 30+, durable receipts |
| Device writes | Generic coercion ignored capability types and limits | Capability existence, read-only, type, numeric-range, and enum checks |
| Discovery output | Device JSON discarded fields; card filtering was ignored in JSON mode | Full individual device JSON and filtered full card definitions |
| Configuration | Commands checked only legacy tokens; nested environment variables were missing; some setup commands needed existing auth | Effective-token checks, explicit environment bindings, config commands available without prior setup |
| Remote connection | Cloud mode sent device API paths to a placeholder account API URL | Explicit selected-Homey HTTPS endpoint and validation |
| Secrets | Short tokens were printed; longer tokens partly revealed; saved permissions were broad | Full display redaction and owner-only saved config/backup permissions |
| OAuth | Callback accepted unsolicited codes, bound all interfaces, and used a global handler | Random state, constant-time check, loopback listener, per-login handler, one delivery, HTTP timeouts |
| HTTP | Redirects could change the destination of authenticated requests | Redirects rejected; only 2xx accepted |
| Dependencies | Old DNS/network modules contained vulnerability advisories | Updated DNS and selected transitive versions; Go baseline 1.25 |
| CI/release | Go version mismatch, old lint config/tool installation, wrong tap-token variable | go.mod-driven Go setup, golangci-lint v2 config/action, separate tap credential |
| Skill/docs | Large command catalog with stale examples and insufficient builder guidance | Provider-neutral workflow, focused references, templates, explicit approval and recovery policy |

## Compatibility evidence

Read-only inspection covered 118 stored flows, including 46 Advanced Flows, and
32 Logic variables. No live flow, folder, variable, device, or setting was changed.
All eight advanced card types were observed. The advanced canvases contained
between 2 and 65 cards.

Real exports established several details that generic examples missed: ordinary
flows can use bare local trigger tokens; optional droptokens can be null; some
existing canvas keys are not UUIDs; ANY joins commonly omit an input array; ALL
joins identify source output ports explicitly. These informed validation and
redacted regression tests. No private flow exports or credentials are bundled.

The structural audit returned zero errors across the 118-flow sample. It reported
18 unreachable-card warnings and 11 non-UUID-key warnings. These are review
signals, not proof that an existing flow is faulty. Online validation of two
Advanced Flows and one ordinary flow also returned zero errors.

## Verification

The implementation is checked with the full Go test suite including the race
detector, go vet, golangci-lint v2, a build, offline template validation, and an
embedded-skill installation compared recursively with its source files.
govulncheck reports no vulnerabilities after dependency updates.

Behavioral regression tests cover backup-before-write ordering, stopping when a
backup fails, partial ordinary-flow updates, AI disabled/folder enforcement,
network-free dry-run, duplicate flow names, strict variable values, collisions,
approval hash invalidation, large-batch requirements, partial-application
receipts, exported null/local tokens, Logic-vs-app variable references, card
deletion payloads, endpoint validation, redirect rejection, OAuth state/replay,
and device capability guards.

Write paths are tested against local HTTP fixtures. Actual Homey writes and a
fresh browser OAuth login were deliberately not performed during this audit.
Read-back checks detect a persisted mismatch but cannot make a write atomic.

## Research and adopted ideas

- [Athom's official CLI](https://github.com/athombv/node-homey) and
  [Web API reference](https://athombv.github.io/node-homey-api/HomeyAPIV3Local.ManagerFlow.html): manager endpoints, complete card discovery, and schema inspection.
- [timvdhoorn/homey-cli-skill](https://github.com/timvdhoorn/homey-cli-skill):
  discovery-first authoring, graph inspection, backups, and practical flow
  pitfalls. Guidance was independently written and adapted to homeyctl.
- [KrauseFx/homey-cli](https://github.com/KrauseFx/homey-cli): capability-aware
  device control influenced the type/range/read-only checks.
- [Homey Logic documentation](https://support.homey.app/hc/en-us/articles/4410240765586-Use-Logic-in-Flows)
  and [card argument documentation](https://apps.developer.homey.app/the-basics/flow/arguments):
  persistent variable types, tags, and argument discovery.
- [Official Homey MCP](https://homey.app/en-us/news/introducing-the-homey-mcp-server/):
  useful complementary conversational access. Its complete live tool catalog
  was not authenticated or tested here; do not assume a capability is absent
  merely because the announcement does not describe it.

## Limits and remaining work

1. **Behavior is not proven by JSON validation.** Online validation currently
   checks installed card IDs and Logic references/types. It does not fully
   validate every app-specific argument, dynamic autocomplete object, zone/user
   reference, token availability along branches, script, cycle, or timing race.
   The skill explicitly requires discovery and behavioral review for these.
2. **No transaction or concurrency lock.** Multi-step variable application can
   be partial. Receipts identify progress. Flow backups preserve the fetched
   version, but concurrent external edits can still race with a write.
3. **Approval is partly an agent responsibility.** Count/hash guards prevent
   accidental application of a different large plan, but any process able to
   invoke the CLI can supply the flags. The skill forbids bypassing thresholds
   through smaller batches. Authentication scopes remain the authority boundary.
4. **OAuth registration still needs owner review.** The pre-existing OAuth
   application credential is distributed in source/binaries and cannot be
   treated as a confidential secret. A provider-supported public-client/PKCE
   design or owner-managed registration/credential rotation is a separate
   integration change. No external credential was rotated in this task.
5. **Homebrew release migration.** `goreleaser check` exits with code 2 because
   its otherwise valid configuration uses the deprecated `brews` publisher.
   This release check is not green. The tap uses a custom private
   download strategy; moving to a different publisher/package format needs a
   deliberate release migration. The cross-repository token mismatch is fixed.
6. **Platform and live-write matrix.** Automated checks ran on macOS arm64.
   Linux CI and Intel release artifacts should pass the configured pipeline
   before release. Exercise create/update/delete/restore on a disposable,
   disabled flow on the intended Homey firmware before deploying this build
   to unattended agents. Review all deletion and read-back behavior there.

## Review and rollout

Use the local build and bundled skill together; an older installed homeyctl
does not support these builder commands. Review the diff, run the checks, then
perform an explicitly authorized disposable-flow test. Release the binary and
skill together. Do not enable production automations as part of a CLI upgrade.

## Follow-up review (2026-09-22)

An independent re-check reproduced the verification claims above: build, `go vet`,
`go test -race ./...`, gofumpt, golangci-lint v2 (0 issues), and govulncheck (no
vulnerabilities) all pass, and `install-skill` writes the eight embedded files
byte-identically to their sources. Live Homey writes remain untested; the Homey
was unreachable from the reviewing machine.

The re-check found seven gaps, all now closed.

| # | Gap | Resolution |
| --- | --- | --- |
| 1 | `.goreleaser.yaml` and `release.yml` referenced a `HOMEBREW_TAP_TOKEN` secret that did not exist, so the next release would fail its tap push | Homebrew distribution dropped entirely; the repo is public, so release assets download without a token |
| 2 | `variables get/set/create/delete` printed JSON unconditionally, contradicting the documented human-readable default | `printVariable` and `printVariablePlan` honour `--json`; the list header formatter was restored |
| 3 | Every runtime error printed the full usage block after the message | `SilenceUsage` set on the root command; exit codes unchanged |
| 4 | `flows update` help advertised `--backup` as recommended while the flag was a no-op | Example replaced with `--dry-run`; the flag is marked deprecated and hidden, still accepted for old scripts |
| 5 | Cloud mode became a breaking config change with no migration note | README documents the upgrade path from 1.3.x |
| 6 | No `flows restore` existed despite the recovery workflow assuming one | `flows restore <backup-file>` added with `--dry-run`, `--to`, backup-before-restore, validation, and read-back, plus five regression tests |
| 7 | The skill's install metadata was dropped in the rewrite | Restored and repointed at the install script |

### Distribution

Releases are GitHub Releases only. `brews` is removed from `.goreleaser.yaml`, so
`goreleaser check` exits 0 and the deprecation blocker in item 5 of *Limits and
remaining work* no longer applies. `install.sh` resolves the latest tag, verifies
the download against `checksums.txt`, installs to the first writable standard bin
directory, and clears the quarantine attribute. Binaries stay ad-hoc signed and
are not notarized.

The `homeyctl.rb` formula was removed from `fishfisher/homebrew-tap`. An existing
`brew install`ed copy keeps working until `brew uninstall homeyctl` is run.

### Live verification against the target Homey

After v1.4.0 was released the Homey became reachable, and the read-only claims
above were reproduced exactly against the live device:

| Claim | Measured |
| --- | --- |
| 118 stored flows | 118 |
| 32 Logic variables | 32 |
| Zero structural errors | 0 errors |
| 18 unreachable-card warnings | 18 `orphan_card` |
| 11 non-UUID-key warnings | 11 `non_uuid_key` |

Online validation of a live flow returned zero errors, confirming the installed
card and Logic reference checks work against a real catalog.

The full write cycle was then exercised on a disposable flow, closing item 6 of
*Limits and remaining work*:

1. `flows create --ai` produced a disabled flow in the root `AI Flows` folder
2. `flows update` wrote a backup, applied a rename plus an added condition, and
   passed read-back verification
3. `flows restore` rolled both changes back from that backup, after backing up
   the intermediate state
4. `flows delete --force` refused without the flag, then backed up and removed it

The flow inventory returned to its original count with zero validation errors.
The validator also rejected a malformed Logic droptoken before any request was
sent, confirming that bad writes stop locally rather than reaching Homey.

### Still open

Items 1–4 of *Limits and remaining work* stand: JSON validation does not prove
behavior, there is no transaction or concurrency lock, approval thresholds depend
partly on agent cooperation, and the OAuth client credential still needs owner
review. Advanced Flow writes were not exercised live; only an ordinary flow was
used for the disposable test. Linux CI now runs on every pull request.
