# Review findings, 2026-09-22

A read-only review of the repo at `5571eb3` (v1.4.1), done right after migrating
this machine off the Homebrew build. Baseline at review time: `go build ./...`
clean, `go test ./...` all green, 13 773 lines of Go, 29 test files.

These are the items left open *after* `docs/audit-2026-09.md` closed its seven

## Context that shapes the work

Homebrew is no longer a distribution channel for homeyctl: the formula is deleted
from `fishfisher/homebrew-tap` and releases are GitHub Releases only. The intent
is to stay off Homebrew, and possibly move the other seven `fishfisher/tap` CLIs
the same way later — homeyctl is meant to become the pattern they copy. So
finding 1 is not a convenience; it is the thing that replaces what `brew upgrade`
used to do, and its shape should be worth copying.

---

## 1. No upgrade path in the CLI

**Evidence:** `grep -rni "self.update|selfupdate|upgrade|latest release|api.github.com" --include='*.go' .` returns nothing.

There is no `homeyctl upgrade` and no version check of any kind. Homebrew used to
provide both. The concrete failure: this machine sat on v1.3.7 while v1.4.1 was
out, and nothing in the tool ever said so — it took an out-of-band nudge to find
out.

**What to build:**

- `homeyctl upgrade` — resolve the latest tag, download, verify against
  `checksums.txt`, replace the running binary in place. `install.sh` already
  implements exactly this logic in shell (tag resolution at `install.sh:57-63`,
  checksum verification at `install.sh:84-99`); port it rather than reinventing.
  Support `--check` (report only, exit non-zero if stale) and pinning to a tag.
- A cached background version check that prints a single line ("v1.4.2 is
  available — run `homeyctl upgrade`") after other commands. Cache the result
  (once a day is plenty) under the OS config dir so it costs nothing per
  invocation, never block or slow a command on it, never let a network failure
  surface as an error, and make it switchable off via config.

**Acceptance:** upgrading from an older tag works end to end and reports the
resulting version; `--check` is accurate both when current and when stale; the
notice appears at most once a day and stays silent when offline.

## 2. `flows enable` / `flows disable` do not exist

**Evidence:** flag registration at `cmd/flows.go:883-908` — no enable/disable
command. `--ai` forces `enabled=false` at `cmd/flows.go:359`.

The review-first workflow's whole point is to create a disabled draft and let a
human turn it on. There is no verb for turning it on. The only CLI route is
`flows update <id> --data '{"enabled":true}'`, which is nowhere documented as the
way to enable something.

`README.md:135-137` says the user reviews the draft in Homey and enables it
there, so this is partly deliberate — but it is the same shape as gap 6 in
`docs/audit-2026-09.md` ("No `flows restore` existed despite the recovery
workflow assuming one"): the documented workflow assumes a command that isn't
there.

**What to build:** `flows enable <id>` and `flows disable <id>`, going through
the existing backup-before-write path, with `--dry-run`. Enabling has real
physical consequences — a flow can fire immediately — so it should say what the
flow does and require confirmation, consistent with the thresholds in
`homey-skill/references/safety.md`.

**Acceptance:** enabling a draft created with `--ai` works and writes a backup
first; `--dry-run` changes nothing; disabling round-trips.

## 3. No way to list the drafts

**Evidence:** `cmd/flows.go:883` — `flows list` registers only `--match`.

`--ai` files drafts in an "AI Flows" folder, but there is no `--folder` filter and
no `--enabled`/`--disabled` filter, so "show me what's waiting for review" can
only be approximated by guessing at names. Pairs with finding 2: together they
are the two halves of the last step in the workflow.

**What to build:** `--folder` and `--enabled`/`--disabled` filters on
`flows list`. Consider the same on `flows audit`, which currently takes no flags
at all.

**Acceptance:** `flows list --folder "AI Flows" --disabled` lists exactly the
pending drafts.

## 4. `install.sh` header documents the wrong default

**Evidence:** `install.sh:8-9` says the install directory defaults to "the first
writable of /usr/local/bin, /opt/homebrew/bin, $HOME/.local/bin". The code at
`install.sh:65` is unconditionally `${HOMEYCTL_BIN_DIR:-$HOME/.local/bin}`.

Stale comment left behind by commit `1ea5b6c` ("Install to ~/.local/bin instead
of Homebrew's prefix"). One-line fix; it rides along with finding 5 since it is
the same file.

## 5. A missing `checksums.txt` is not fatal

**Evidence:** `install.sh:95` warns and installs anyway.

For something invoked as `curl … | sh`, "could not fetch checksums.txt" should
stop the install, with a deliberate opt-out (`HOMEYCTL_SKIP_CHECKSUM=1`) for
whoever genuinely needs it. Same for the case where neither `shasum` nor
`sha256sum` exists — today that path silently skips verification without saying
so.

## 6. Two parallel version mechanisms

**Evidence:** `main.go` sets `version`/`commit`/`date` and calls
`cmd.SetVersionInfo` (`cmd/root.go:29-35`). Separately `cmd/root.go:57` declares
`var version string`, consumed by `buildVersion()` (`cmd/root.go:59`) and used at
`cmd/root.go:82`. `.goreleaser.yaml` sets ldflags for *both* `main.version` and
`github.com/fishfisher/homeyctl/cmd.version`.

Works today because goreleaser populates both. It is still two sources of truth
for one fact, and a release that sets only one would produce a confusingly
half-right `--version`. Collapse to one. Worth doing as part of finding 1, which
touches version handling anyway.

## 7. Shell completion is undocumented

**Evidence:** `grep -n "completion" README.md` returns nothing.

Cobra provides the `completion` command for free and it is never mentioned. For a
CLI with ~20 command groups whose arguments are opaque UUIDs, completion is a
real ergonomic win. Document it in the README, and consider offering to install
it from `install.sh`.

## 8. `devices list` has no `--zone` filter

**Evidence:** `cmd/devices.go:201` registers only `--match`, though `Zone` is
already on the struct at `cmd/devices.go:18`.

Small, but zone is the natural way to narrow a device list in a house.

## Working agreement

- `AGENTS.md` governs: conventional commits, `make fmt` (gofumpt), `make lint`
  (golangci-lint), `go test ./...` before shipping.
- Add regression tests for findings 1, 2 and 3 — the existing
  `cmd/flows_safety_test.go` is the model for how write paths get covered here.
- Do not push, tag, or release without Erik asking explicitly. A release happens
  by pushing a `v*` tag, which triggers `.github/workflows/release.yml` →
  goreleaser → GitHub Release with `checksums.txt`.
- After a release, this machine upgrades with
  `curl -fsSL https://raw.githubusercontent.com/fishfisher/homeyctl/main/install.sh | sh`
  and then `homeyctl install-skill --force --path ~/.claude/skills` to refresh the
  bundled skill.
